> Workspace facts not covered by the ai-spector scaffold: active Claude Code hooks, npm scripts, and repo layout

# Local workspace

Root `CLAUDE.md`, `WORKFLOW.md` and `prototype/CLAUDE.md` are **generated by ai-spector** and are
refreshed from `node_modules/ai-spector/scaffold/claude/` by `npx ai-spector sync-claude`. Edits to
those files are lost on the next sync or upgrade — put durable project context here or in
[project.md](./project.md) instead.

## Hooks that change what your writes do

Configured in `.claude/settings.json`; both run automatically and neither is mentioned in the
scaffold.

| Hook | Effect |
|------|--------|
| `.claude/hooks/block-env-edit.sh` (PreToolUse `Write\|Edit`) | **Denies** writes to `.env` and `.env.*`. Only `.env.example` / `.env.sample` / `.env.template` pass. Ask the user to edit real env files themselves. |
| `.claude/hooks/format-ts.sh` (PostToolUse `Write\|Edit`) | Runs `prettier --write` then `eslint --fix` on any `.ts`/`.tsx` under `backend/` or `frontend/`, from that submodule's root. **The file on disk will differ from what you wrote.** Silently skips when the submodule has no `node_modules`; unfixable lint errors come back as additional context. |
| `.claude/hooks/log-skill-read.ts` + `kaopiz-devkit remind` (UserPromptSubmit, PreToolUse `Skill`/`Read`) | Telemetry and DevKit step reminders. No effect on file contents. |

## Layout

One repo: application code in the `backend/` and `frontend/` submodules, SRS/design docs in the
`docs/` submodule, ai-spector/DevKit state at the root. See [project.md](./project.md) for
submodule commit rules. The `security-reviewer` and `stack-verifier` subagents are scoped to
`backend/` and `frontend/`.

## npm scripts (root)

```bash
npm run kaopiz-devkit -- <cmd>   # DevKit CLI (start/step/approve/run) — see kaopiz-devkit-current-instruction.md
npm run devkit:sync              # refresh .claude/ commands+skills from the DevKit hub, then handbook data
npm run handbook:serve           # devkit:sync, then serve the handbook locally
npm run devkit:mcp-start         # vibe-coding MCP server
```

`.vibe/` holds no `active.json` or `sessions/` — there is **no active DevKit session**, so the
session rules in `kaopiz-devkit-current-instruction.md` do not apply until one is started.

## Git hooks

Managed by the `pre-commit` framework (`.pre-commit-config.yaml`), fail-fast in order: PII scan →
gitleaks → quick lint → ai-spector `graph validate` (only when `docs` or `.ai-spector/graph/`
is staged) → commit message must contain `[SPEC-XXX]`.

**Do not run `npx ai-spector hooks install`** — it overwrites `.git/hooks/pre-commit` and drops
the other checks. Bypass once with `git commit --no-verify`.
